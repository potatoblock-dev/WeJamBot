# 能力边界

这份文档说明**哪些能做、哪些做不到、为什么**。结论都来自实测，不是推测。

:::info 与 wxauto 系工具的差异根源
wxauto(x4) 基于 **Windows UIAutomation**，对每个 UI 元素都有细粒度句柄。
本项目对接 **Linux 版微信 + AT-SPI 无障碍树**，树里能拿到的东西少得多 ——
这不是实现深浅的问题，是底层暴露能力的问题。
:::

## ✅ 已支持

| 能力 | 接口 |
|---|---|
| 会话列表（含未读数 / 置顶 / 免打扰） | `wx.chats()` |
| 读取消息（自动打开目标会话） | `wx.messages(chat=...)` |
| 发送文本（中文 / emoji，不经输入法） | `wx.send(text, chat=...)` |
| 全局监听（所有会话，不动界面） | `wx.watch()` |
| 单会话精细监听（拿完整正文） | `wx.watch(chat=...)` |
| 区分自己发的消息 | `msg.from_self` |
| 未读徽标 | `wx.badges()` |
| 登录状态 / 二维码内容 | `wx.login_state()` / `wx.qr_code()` |
| 消息右键动作（复制 / 转发 / 收藏 / 引用 / 提醒 / 翻译 / 多选） | `wx.copy_message()` / `wx.message_action()` |
| 逃生舱：节点树 / 按名点击 | `wx.tree()` / `wx.click_node()` |

## ⚠️ 部分支持

| 能力 | 现状 |
|---|---|
| 消息类型（文本 / 图片 / 表情 / 文件…） | 只能从**文本标记**推断（`动画表情`、`[图片]`、`[文件] x.py`），不是写明的类型字段 |
| 群聊消息的发送者 | **消息级拿不到**。消息在树里是扁平文本，发送者名字是**画出来的**；只有**会话列表的预览**里带发送者 |
| 消息 ID | 我们的是派生值（时间桶 + 正文 + 出现次序），不等于 UI ID；界面滚动后可能变化 |
| 历史消息 | 只能读当前渲染出来的部分；向上滚动加载**尚未实现** |
| 会话类型（好友 / 群 / 公众号） | 可从会话名与预览推断，没有权威字段 |

## ❌ 做不到

### ~~消息级右键操作（根本阻塞）~~ → ✅ 实际可行

:::warning 更正
本文档早期版本断言「右键不弹菜单、消息级操作不可做」。**那是错的** ——
我当时的探测点在消息行的**空白处**，不是气泡上。实测修正后，右键菜单完全可用。
:::

消息级右键菜单**可以弹出，并且菜单项在无障碍树里**：

```
[menu item] '复制'      [menu item] '转发...'    [menu item] '收藏'
[menu item] '放大阅读'   [menu item] '多选'       [menu item] '提醒'
[menu item] '翻译'      [menu item] '搜一搜'     [menu item] '引用'
[menu item] '删除'
```

实测端到端（复制一条消息并取回正文）：

```bash
$ wejam copy 7 --chat 文件传输助手
复制的正文: '.'
```

**三个必须知道的细节**（都踩过）：

| 细节 | 说明 |
|---|---|
| 右键要带指针微移 | 纯 press+release **无论按多久都不弹菜单**；「按下 → 移动 2px → 抬起」才弹 |
| 要点在气泡上 | 无障碍给的 list item 是**整行宽度**，行中央往往是空白 |
| 菜单项按名字点 | 菜单是独立窗口，`menu item` 带名字，不需要记坐标 |

**限制**：

- 图片 / 表情 / 语音等消息的菜单**不一样**（没有「复制」），需要按类型分别处理
- 部分滚动裁切的消息行可能定位失败
- `删除` / `撤回` 属于不可逆动作，**服务端默认拒绝执行**

### 微信客户端自带能力

- `msg.ocr()`：那是 Windows 版微信的内置 OCR。本项目做 OCR 就违背「不用 OCR」的定位
- `msg.to_text()`：语音转文字，同样是客户端能力

### 高风险 / 未验证

| 能力 | 说明 |
|---|---|
| 好友申请处理、添加好友、改备注标签 | 联系人页可读，但涉及多步交互且属于高风险操作，不做 |
| 朋友圈读取 / 发布 | 独立窗口，未验证；发布属于高风险 |
| 发送文件 / 语音 / 图片 | 需要文件对话框或拖拽，未验证 |
| @所有人 | 群聊输入框的 @ 交互，未验证 |

## 与 wxauto 接口的对应关系

| wxauto 风格 | 本项目 |
|---|---|
| `wx.ChatWith(who)` | `wx.messages(chat=who)` 会先打开该会话 |
| `wx.GetSession()` | `wx.chats()` |
| `wx.SendMsg(msg, who=...)` | `wx.send(text, chat=...)` |
| `wx.GetAllMessage()` | `wx.messages()` |
| `wx.AddListenChat` / `StartListening` / `KeepRunning` | `wx.watch()`（服务端轮询，客户端只收流） |
| `wx.SwitchToChat()` / `SwitchToContact()` | `wx.click_node("push button", "微信" / "通讯录")` |
| `WxParam.LISTEN_INTERVAL` | 服务端轮询间隔（agent 内部常量） |
| `WxResponse` | `bool` 或抛异常（gRPC 状态码） |
| `msg.attr == 'self'` | `msg.from_self` |
| `msg.type == 'text'` | `msg.kind == 1` |

:::tip 一个反而更强的地方
wxauto 的监听模型要求给**每个**目标开一个独立 `Chat` 子窗口（`AddListenChat`），
因为 Windows 版切换会话会丢 UI 元素。

本项目的全局监听**只读会话列表的预览**，覆盖**所有**会话且**不打开任何窗口** ——
不动界面、不清未读。代价是只能拿到预览文本，见[快速开始](/quickstart#监听新消息)。
:::
